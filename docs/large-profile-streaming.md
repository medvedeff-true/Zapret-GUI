# Большие списки: подготовка и передача в службу

## Что изменено

Протокол службы версии 2 передаёт JSON только для команд, аргументов и размеров
файлов. Содержимого файлов и пользовательских путей в JSON нет.

Клиент читает файлы порциями по 256 КиБ. Текстовые списки сжимаются gzip level 1
отдельно для каждого блока. Если экономия меньше 5%, клиент отключает компрессию
для оставшейся части файла. Бинарные payload-файлы и готовые `.gz` передаются
без повторного сжатия.

Служба проверяет размеры блоков **до выделения памяти**, ограничивает распаковку
одним блоком, проверяет фактический размер и SHA-256 каждого файла и пишет
данные непосредственно в служебный временный каталог. Запуск `winws` происходит
только после успешного приёма всех файлов.

Повторные ссылки на один путь передают файл один раз. Прерванный поток не
переигрывается; соединение закрывается, временные файлы удаляются. Остатки
каталогов после аварийного завершения службы очищаются при следующем запуске.
Отмена/закрытие контроллера прерывает передачу между блоками.

Существующая проверка версии протокола и хеша helper автоматически потребует
переустановку службы при несовпадении. При первом запуске новой сборки может
понадобиться подтверждение UAC.

## Ограничения

- До **8 ГиБ** суммарного содержимого файлов в одном профиле, до 256 файлов.
  Это предел приёма, а не обещание, что `winws` сможет эффективно индексировать
  такое количество доменов. Память самого `winws` зависит от его реализации.
- Бинарные DPI-payload и файлы raw-фильтров ограничены отдельно: **16 МиБ**.
- JSON-команда/ответ: до **1 МиБ**. Блок: до **256 КиБ**, и до и после распаковки.
- Проверяется свободное место для несжатых файлов с запасом 64 МиБ.
- Таймаут отсутствия данных и общий предел времени защищают службу от зависшего
  или недобросовестного клиента.
- Уже сжатый исходный `.gz` сохраняется как `.dat.gz`; его внутренняя распаковка
  относится к `winws`, а не к транспортной компрессии.

## Объединение списков и менеджер сайтов

Runtime-списки строятся потоково. Для небольших файлов используется обычное
множество; начиная с 4 МиБ — временный SQLite-индекс с ограниченным кешем
4 МиБ. Удаление повторов точное, регистр не учитывается, порядок первых
вхождений сохраняется. Файл результата заменяется атомарно.

Подписи входных и выходного файла кешируются в `*.merge.json`. Если размеры,
времена изменения и идентификаторы файлов не изменились, повторное объединение
не читает списки заново. Это оптимизация, а не контроль целостности против
намеренного изменения файлов с подделкой их метаданных.

Ошибки подготовки блокируют запуск, а не подменяют новые данные старым списком.
Пользовательский оригинал не меняется при подготовке runtime.

Импорт TXT/CSV и поиск выполняются в рабочих потоках. В большом списке окно
показывает первые 1000 совпадений и предлагает уточнить поиск; остальные записи
не исключаются из обхода. JSON-импорт ограничен 16 МиБ: для больших наборов нужно
использовать потоковые TXT/CSV. Максимальная длина обычной строки — 64 КиБ.

Память экономится за счёт последовательного чтения, временного дискового индекса
и отсутствия Base64. Цена — дополнительное место и ввод-вывод на диске при первом
объединении. Неизменившийся runtime повторно не строится.

## Проверка производительности

```powershell
.\.venv\Scripts\python.exe tools\benchmark_profile_streaming.py --size-mib 1024
```

Тест использует отдельный `--test-host` и инертный engine: не устанавливает
службу, не открывает WinDivert, не включает обход. Требует место для исходного
и принятого файла. Данные синтетические; это проверка транспорта, **не**
скорости/памяти реального `winws` или первичного SQLite-объединения.

Локальный замер 14 ноября 2026 года:

| Исходный файл | Передано | Время с запуском тестового engine | Пик Python-аллокаций | Прирост RSS клиента | Прирост RSS службы |
|---|---:|---:|---:|---:|---:|
| 128 МиБ | 12,69 МиБ | 1,77 с | 0,68 МиБ | 1,47 МиБ | 16,17 МиБ |
| 256 МиБ | 25,38 МиБ | 2,27 с | 0,68 МиБ | 1,38 МиБ | 16,35 МиБ |
| 1024 МиБ | 101,52 МиБ | 5,30 с | 0,68 МиБ | 1,40 МиБ | 16,39 МиБ |

SHA-256 исходника и принятого файла совпал во всех трёх случаях. Время и степень
сжатия зависят от данных, оборудования и состояния дискового кеша. RSS не
включает весь системный файловый кеш; это не суммарный расход ресурсов ОС.

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_bypass_service tests.test_large_lists tests.test_large_lists_gui -v
```

Проверка реального `winws --dry-run` требует административного токена и при его
отсутствии пропускается. Все встроенные BAT отдельно проверяются новым протоколом
с инертным engine; эта проверка не заменяет проверку аргументов реальным `winws`.
